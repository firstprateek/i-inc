# Ticket #24 — PR notes and validation

GitHub imports keep the repository's package manager when the package has no check
scripts, including before a lockfile exists. Imports without an explicit recipe
now inspect the repo and retain its detected checks, protected paths and default
branch. GitHub response reads have a deadline even if a body ignores abort, and a
contents-fetch failure cannot turn a known populated repo into an empty one.
Python scaffold descriptions escape TOML control characters without losing text.

## Risk and owner choices

An API import without checks now makes inspection requests and reports their
failure instead of silently registering pnpm commands. Explicit recipes continue
to work without that inspection. Lockfiles retain their existing precedence over
packageManager; the owner could choose a different conflict policy. Starter
creation still defaults to pnpm, and force still offers resume only. Broader
replacement controls would need a separate per-file choice flow.
