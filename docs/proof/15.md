# Ticket #15 proof

Verified implementation `ffd101e` on branch
`inc/15-attach-images-to-an-existing-ticket-and`. Structured evidence, including
session-entry file hashes and brief excerpts, is in [15.json](15.json).

The built web app ran on Bun at `127.0.0.1:57200`, within the assigned port range.
Chromium used the actual file pickers and send buttons; the validation matrix used
HTTP requests. The daemon used an isolated SQLite database and the production
`GitHubWorkspace`, executing its scripts in real local Git worktrees. Agent,
machine, helper, checks and GitHub PR responses were controlled fixtures. This
proves local application behavior; it does not exercise Apple containers, a remote
GitHub service or a live ACP model.

| Acceptance item | Result | Observed evidence |
| --- | --- | --- |
| Add images to an existing ticket and a Not quite reply with the new-ticket checks and limits | Pass | Chromium uploaded `running.png` using Send 1 image and `reply.png` using Request changes with a note. Both succeeded. All three HTTP upload paths rejected SVG, SVG disguised as PNG, seven files and a file over 10 MiB with HTTP 400. Rejected requests stored no additions. Six files per request and 24 per ticket succeeded; exceeding 24 failed, including through Request changes. Image download bytes matched the upload. Missing upload headers returned 415; unknown and completed tickets returned 404 and 409. |
| Inform a running session of new images and copy them before its next turn | Pass | The first Build remained running after upload, with no premature copy. After the controlled agent completed Build, the next Ada session (Report) entered with the image already on disk and the added-images notice in its brief. The API event log ordered owner-attached, attachments-copied, then session-started. The subsequent Request changes Build entered with the reply image and note. All three recorded file hashes matched the uploaded bytes. |
| Tests cover a running ticket and one waiting on the owner | Pass | Existing core and daemon attachment tests cover both states and passed. The live checks also repeated both: a second ticket paused at its plan gate accepted `waiting.png` and stayed needs-you; after approval its first Build entered with the image on disk and announced in the brief. |

The browser also exercised desktop (1440×900) and mobile dark (390×844) views,
with no uncaught page errors. Screenshots and the temporary fixture server were
kept outside the worktree under `/tmp/inc15-proof` during verification.

Required checks passed in order: `pnpm install --frozen-lockfile`, `pnpm check`,
`pnpm typecheck`, `pnpm test`. Test totals: 103 core, 250 daemon, 315 web, plus the
host helper regressions. The production web build also passed. No implementation
changes were needed in this proof stage.
