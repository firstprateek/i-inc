# Coordination: Claude ⇄ Antigravity ⇄ Codex

The single source of truth for who does what. All agents `git pull` before reading this file and
push after changing it. Edits to this file go straight to `main` (commit message `coord: …`); all
other work goes through a branch and PR. [architecture.md](architecture.md) is the design;
[handoff.md](handoff.md) is background.

## How we work

- **Lanes, by folder.** `web` (Claude): `apps/web`, UI and design. `daemon` (Antigravity):
  `apps/daemon`, `packages/core`, `tools/host`, `images/`, the mini. Never edit the other lane's
  folders; if a task needs both, write its contract under **API contracts** first and split it.
- **Claim before working:** set the task's Status to `claimed (<agent>)`, add a `CLAIM` log line,
  commit and push. Never take a task the other agent has claimed.
- **One branch and PR per task** (`t<ID>-<slug>`). The other agent reviews it (`REVIEW` in the
  log): read the diff, run `pnpm check && pnpm typecheck && pnpm test`. Merge when CI is green and
  an independent review is recorded on GitHub and in this log. Never merge unreviewed work.
  Reviewers run all three checks plus a real demo/browser run at 1440x900, 1280x720,
  390x844 touch, 320x568 and 844x390, light and dark, tapping every phone tab.
- **The mini:** add `DEPLOY-LOCK <agent>` to the log before deploying or changing anything there,
  and `DEPLOY-UNLOCK <agent>` after. Ask the owner before any `sudo`, sign-in or network change.
- **The owner:** a task that needs them gets `QUESTION <task> → owner: …` in the log; carry on with
  other work meanwhile. Whoever hears the answer writes it as `ANSWER`.
- **Each loop:** pull → read → handle log lines addressed to you → review PRs waiting on you →
  take the highest open task in your lane → work → push → update this file → wait ~5 min (the owner set a 5-minute cadence on 2026-10-17; both agents check this file that often).
- **Rules that always hold:** the repo is public (no secrets, tokens, account names or home
  addresses); conventional commits, no model names; never weaken the walls; UI changes get checked
  with `tools/ui-check/check.mjs` at 1440x900 and 390x844, light and dark.

Log format: `YYYY-MM-DD HH:MM <from> → <to>: <VERB> <task> — <text>`, with verbs CLAIM, DONE,
HANDOFF, REVIEW, BLOCKED, QUESTION, ANSWER, DEPLOY-LOCK, DEPLOY-UNLOCK. Newest at the bottom.

## Goals (only the owner changes these)

1. **A polished product the owner uses daily, on laptop and phone:** seamless, easy, responsive.
2. **One short address that works anywhere:** a Tailscale Service, `https://iinc.<tailnet>.ts.net`,

3. **The local agent** (OpenCode on Ollama) available in the product.
4. **Dogfooding:** i.inc improves i.inc, with the owner giving suggestions through the product.

## API contracts

**C1 `GET /api/sandboxes`** → `{ "sandboxes": [{ "team": "engineering", "machine": "inc-engineering",
"state": "running" | "stopped" | "missing" | "error", "cpus": 6, "memory": "12G",
"signedIn": { "claude": boolean, "antigravity": boolean, "github": boolean }, "launcher"?: "needs-update" }] }` (`launcher` is set when the machine's launcher writes no agent notes, so a leftover agent can't be found there: run `sh tools/host/update-machine.sh <team>`; Setup → Sandboxes says so)

**C2 Web Push** → `GET /api/push/key` → `{ "publicKey": "<VAPID public key>" }`;
`POST /api/push/subscribe` with a browser `PushSubscription` JSON → `{ "ok": true }`;
`POST /api/push/unsubscribe` `{ "endpoint" }` → `{ "ok": true }`. Notifications carry
`{ "title", "body", "url": "#/ticket/<id>" }`.
**T65 additions (conversations), all additive:** a notification may also carry `"tag"` (one notification per tag; a newer one replaces the older and still alerts; the worker's default is the `url`). Every push shows a notification: there is no push that only closes one, because a push that shows nothing spends Chrome's allowance for silent pushes (after which Chrome shows "This site has been updated in the background") and makes Apple revoke the subscription. A conversation's push is `{ "title": "<Employee> needs you", "body": "<what it wants, at most 120 characters>", "url": "#/conversations/<id>?card=<toolCallId or requestId>", "tag": "conv-<id>" }`; **the body is a short label and nothing else, because it shows on a lock screen.** A command is its program and at most two well-known subcommand words from a fixed list (`Run: pnpm test`, `Run: git commit …`, `Run: mysql …` with an ellipsis when arguments were left out; leading `VAR=value` words and the path to the program are dropped), and `Run a command` when the program is not a plain name: a command's arguments are never shown, because a password or token may be one, and the characters of a command are never altered. A file is its path inside the project, only when it is plain characters (`Edit: src/my_file.ts`, `Delete: old/file.txt`, else `Edit a file`); a fetch is its host (`Fetch: github.com`, else `Fetch a page`); a search is `Search the project`; anything else `Wants to use a tool`. The only model-written prose that can appear is a question's text (`Asks: <question>`) and a conversation's title (the finished push): markup stripped, the full redaction (`redactText`) applied, one line, cut hard (80 and 120 characters), with the working-copy path removed. The tool's input, a diff, file contents and a command's arguments never are. The link carries only ids. The turn-finished push is `{ "title": "<Employee> finished", "body": "<conversation title>", "url": "#/conversations/<id>", "tag": "conv-<id>" }`. **Nothing is sent when a request is answered or ends.** The app closes stale notifications itself (`apps/web/src/notifications.ts`): when it opens, regains focus or moves to another conversation it closes the notifications (`registration.getNotifications()`, by `conv-<id>` tag) of conversations that are not waiting any more, and every one of the conversation in front of the owner; a "finished" notification stays until its conversation is opened. **When it is sent** (apps/daemon/src/ahp/conversation-push.ts, listening to the host with `AhpHost.observe`): a permission or question that appears in a conversation's "Needs you" list waits a 20 s grace; answered within it (on any device) nothing is sent; at the end of it, if an authenticated client is watching that conversation (below) it looks again every 10 s until the request is answered or nobody watches; otherwise one push per request, ever (`push_sent` key `convpush:<inputNeeded id>:<turn id>`, kept 7 days; a request over 24 h old is not pushed). A request ending (answered, its chat's turn ended or stopped, the conversation archived) just stops its wait. **After a restart** (every deploy): the host ends the turns that were running, so a request is normally gone; one found still waiting gets a fresh grace and is pushed only if it never was. The module is closed first on shutdown, so the turns that stopping ends do not send anything. Turning "Conversations need me" off drops the requests still in their grace. `push_sent` keys of conversation pushes are pruned after 7 days, hourly. Delivery failures are logged without the subscription's endpoint. Optional, off by default: a turn that ran 60 s or more and completed while nobody watches gets the finished push. No tool input, no model-written text and no attachment ever goes into a push. The worker shows no action buttons (iOS has none); a tap focuses an open window, navigates it where it can, sends it `{ "type": "i-inc:open", "url" }` (the app follows only a same-origin `#/` address) or opens a window; approving is done in the app, never from the lock screen. **Settings:** `GET /api/push/settings` → `{ "settings": { "conversationsNeedMe": true, "longReplyFinished": false } }`; `PUT /api/push/settings` with any of those as booleans → `{ "settings" }`, or 400 `{ "error" }` for an unknown key or a non-boolean (nothing changes). Stored in the company settings (`settings.notify`), one choice for every device, read when it matters. There are no other global quiet settings. Setup → Notifications shows both toggles under "What to be notified about". A copy is removed from the machine an employee no longer works in (they moved team or left; also when the registry changes) and the pages of a deleted brain repo leave the copy. `RunScript` takes an optional `{ machine }` for that. A copy is never made or removed by starting a machine (`machine ls` says what is running, `BrainFeed.isUp`); a removal that couldn't be done stays recorded (`brain_synced`) and is done by the next pass (before a copy, on registry changes, every 10 minutes). **C22 Conversations over AHP (T59a)** → REST, behind the same login, Host and Origin guards as the rest of the API (writes are JSON): `GET /api/conversations[?archived=true|all][&employee=<id>]` → `{ "conversations": Conversation[] }` (live ones by default, newest activity first); `GET /api/conversations/:id` → `{ "conversation" }` (404); `POST /api/conversations` `{ "employeeId", "project"?: string | null, "title"?, "mode"?, "engineId"? }` → 201 `{ "conversation" }` (400 unknown employee, project, engine or mode or a bad title; 409 the employee doesn't work on that project; 502 the agent side could not open; `engineId` defaults to the employee's build engine, `mode` to the agent's own default, which is its bypass-permissions mode); `PATCH /api/conversations/:id` `{ "title"?, "archived"?: boolean }` → `{ "conversation" }` (renames and archives both the row and the AHP session; archiving is how a conversation is put away, nothing is deleted). `Conversation` = `{ "id" (8 hex), "employeeId", "project": string | null, "branch": string | null` (`conv/<id>`, null with no project)`, "title", "mode": string | null, "engineId", "createdAt", "archivedAt": number | null, "ahpSession", "ahpChat", "status": number` (AHP `SessionStatus` bits: 1 idle, 2 error, 8 in progress, 24 input needed, 32 read, 64 archived)`, "needsYou": boolean, "running": boolean, "modifiedAt": number }`. Table `conversations(id, employee_id, project, branch, title, mode, engine_id, created_at, archived_at, ahp_session, ahp_chat)`. The working copy is `/home/employee/work/conv-<id>` in the employee's team sandbox (T59b creates it; "no project" is an empty scratch folder). **`/ahp`** is a WebSocket upgrade on the daemon's own port speaking [AHP](https://microsoft.github.io/agent-host-protocol/) **1.0.0** with the official `@microsoft/agent-host-protocol` 1.0.0 types and reducers (the package is pinned exactly; it has no host, ours is `apps/daemon/src/ahp/`), one JSON-RPC message per text frame. Upgrade: 401 without the `i_inc` cookie or `Authorization: Bearer` (no `?tkn=`: tokens in URLs get logged), 421 for an unknown Host, 403 for a foreign Origin (no Origin passes, like the REST API), 503 when 32 connections are open; with `I_INC_AHP_DEFERRED_AUTH=1` a client may upgrade without credentials and must push the token with the spec's `authenticate` within 10 s (three bad tries close it); otherwise `authenticate` is accepted as a no-op. Version: only `1.0.0` is offered (anything else is `-32005` with `data.supportedVersions`); `initialize` or `reconnect` must come first (`ping` and `authenticate` may precede). Channels: `ahp-root://` (`agents`: one provider per engine id), `ahp-session:/<uuid>` (one per conversation: `title`, `status`, `config` = the agent's own modes and options with `mode` as the permission mode (default: its bypass mode), `inputNeeded` = the "Needs you" list of pending confirmations and questions across chats, `_meta`), `ahp-chat:/<uuid>` (one per session; its turns).
